# Legacy Source Audit and Retrieval Index

## Status

**Active reference / retrieval control — not setting canon.**

This page exists because `legacy-notes/` is **not a trash folder**.

The raw files there preserve provenance, contradictions, discarded designs, research, and earlier versions of the setting. Some of that material is obsolete. Some has already been reconciled into current owner pages. Some remains genuinely useful and has **not yet been reconciled**.

The danger is not that legacy material exists.

The danger is either:

1. treating old material as canon because it is detailed; or
2. forgetting useful material exists because it was filed as legacy.

This page prevents both.

## Retrieval rule

Before inventing substantial new material in a topic marked **UNRECONCILED** or **PARTIALLY RECONCILED** below:

1. read the current owner first;
2. inspect the relevant legacy volume / section listed here;
3. classify useful material as compatible, conflicting, duplicate or unknown;
4. promote only mechanisms or details that survive current World Rules;
5. record the disposition in [Source Register](Source-Register.md).

Do **not** reread the whole legacy archive for every task.

Use this page as the routing layer.

# Classification

## COLD PROVENANCE

Keep for history / traceability.

Normally do not consult unless reconstructing an earlier design decision.

## RECONCILED

The important mechanism has an active owner or reference.

Legacy remains provenance and an idea quarry.

## PARTIALLY RECONCILED

An active owner exists, but the legacy volume contains material that has not received a deliberate modern pass.

Check it before expanding that topic.

## UNRECONCILED / HIGH SALVAGE VALUE

Legacy contains significant forward-relevant material not represented adequately by current owners.

Do not treat it as canon, but do not design the topic from scratch without reviewing it.

## 4. Grounded domino design

Volume 12 contains forward-relevant story method:

- show effects before plans;
- reveal systemic pressure through ordinary scenes;
- let rumors and incomplete information carry clues;
- use small incidents that actors have independent reasons to escalate;
- connect micro-crises into larger cascades;
- let trusted institutions fail for understandable reasons.

This is not obsolete lore.

**Action:** extract the durable method into an active Reference page rather than relying on agents to rediscover Volume 12.

## 5. Missing world-system categories

These should not be filled from the generic legacy guide as facts.

But they should remain visible as **known worldbuilding gaps**.

# Material that is correctly left in legacy

Legacy is the correct home for:

- rejected names;
- discarded maps;
- alternate plot structures;
- superseded regional labels;
- theme-first festivals;
- fantasy races no longer supported by current rules;
- direct Earth-culture copies;
- old deity systems that conflict with current faith structure;
- obsolete characters;
- old recipes and costume inventories;
- failed or superseded Council models;
- brainstormed gangs, armies or kingdoms not deliberately promoted.

Keeping these is useful because they preserve provenance and sometimes explain why current rules exist.

They just should not compete with active owners.

# Redundant packaging

The consolidated package also includes duplicate packaging such as the all-in-one compendium and nested archive.

These are useful for provenance but **should not be normal retrieval targets** because they duplicate material already split into indexed volumes and make search results noisier.

Preferred retrieval order:

1. current owner;
2. this audit;
3. relevant consolidated thematic volume;
4. original/direct source only when provenance or wording matters;
5. all-in-one duplicate package only as a last resort.

If repository size or search noise becomes a problem, the duplicate package files are the first candidates for cold-storage removal **after** verifying their content is fully represented and hashes/provenance are preserved.

# Completion rule

A legacy topic is not "handled" merely because:

- its file was imported;
- Source Register mentions its volume;
- an active page exists with the same broad title.

It is handled when its relevant mechanisms have been deliberately classified as:

- promoted;
- rejected;
- duplicate;
- still unresolved.

Until then, this index should mark it PARTIAL or UNRECONCILED.
